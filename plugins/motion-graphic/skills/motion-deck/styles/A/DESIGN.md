# 스타일 A 「무대」 — 검정 무대, 불은 한 번에 하나

> 검정 무대에 한 번에 하나만 불을 켠다. 큰 글자가 움직이며 말하고, 카메라가 이야기를 따라간다.
> 화면 보기: `preview.html`(더블클릭) · `shots/sheet.png` · 필름 `shots/*-film.png`. 덱 전체에 쓰는 공통 규칙은 `references/rules.md`.

## 언제 고르나
- **어두운 홀·큰 행사장**에 맞는다(무대 조명, 스크린이 큼). 밝은 회의실이면 검정이 회색으로 떠서 대비가 줄어든다(B 나 C 가 안전).
- 큰 문장·키네틱 타이포·카메라 이동처럼 **영화적인 몰입**이 필요한 발표에 맞는다.
- 사용법·체크리스트처럼 글이 많은 장이 많으면 검정 바탕은 읽기 피로가 크다.

## 1. 화면
- 1920×1080, 바탕 `#000`. **크롬 없음**: 챕터 라벨, 푸터, 쪽번호, 진행 바, 범례 줄, 로고 줄을 두지 않는다.
- 왼쪽 세로선 **x = 160** 이 기본 여백이다. 의도된 비대칭이고 오른쪽은 비워 둔다. 장마다 구도는 달라도 이 세로선으로 한 시스템으로 읽힌다.

## 2. 색 (`theme.css` 의 `.dir-a` 토큰)
| 토큰 | 값 | 쓰임 |
|---|---|---|
| `--fg` | `#fff` | 글자, 장치(관문) 외곽선 |
| `--mute` | `#A4A3A4` | 보조 글자(검정 위 8.3:1), 쌓인 라벨 |
| `--hu` | `#E36007` | **사람·주인공**. 글자로 써도 된다(검정 위 5.94:1) |
| `--ai` | `#00854A` | **AI·진행**. **면과 선으로만** 쓴다(검정 위 초록 글자는 4.45:1 로 불합격) |
| `--dim` / `--line` | `#666` | 지나간 부품, 갈 길 점선 |
| `--off` | `.28` | 꺼진 조명(글자 불투명도) |

- 그 밖의 DB 색은 꼭 필요할 때만: 하늘 `#0085CA`(검정 위 5.2:1), 청록 `#3BA096`(6.7:1), 연두 `#86BC25`.
- **네이비 `#002060` 은 검정 위에서 보이지 않으니 쓰지 않는다.**
- 다른 브랜드 색으로 바꾸려면 위 토큰만 바꾼다. 글자로 쓰는 색은 검정 위 4.5:1 이상이어야 하고, 캡처 검사가 확인한다.

## 3. 조명 규칙
- 지금 말하는 것만 100% 밝다. 지나간 것은 꺼진 조명이다(글자 `--off`, 도형 `--dim`).
- 결론 상태에서 읽혀야 할 글자는 켜 둔다(대비 4.5:1 이상). 꺼진 글자는 "읽지 않아도 되는 맥락"일 때만 쓴다.

## 4. 타이포
- **크기 사다리**(1920×1080 실효 px): 타이틀 300 · 큰 문장 150~190 · 장 제목·요약 110~128 · 비트 이름 100 · 부제·설명 56~72 · 누가·라벨 44~46. 최소 40px(타이틀의 행사·발표자 줄만 32px 이상 허용).
- 굵기: 디스플레이 820, 라벨·설명 600.
- 자간 −0.03em, 150px 이상은 −0.035em. 라틴↔한글 경계(「AI가」)는 키를 나눠 +0.02em 띄운다(`.kb`).
- 행간: 디스플레이 1.04~1.12, 설명 1.3. `word-break: keep-all` + `text-wrap: balance`.
- 라틴 옆 한글 조사는 0.76em 으로 줄여 같은 바닥선에 앉힌다(샘플 타이틀의 「로」, `.t-ro`).

## 5. 모션
- **글자**: 새 글자는 자기 바닥선 아래에서 떠오른다(`data-in="mask"` / `data-enter="mask"`, .8~.9s, 단어 간격 40~90ms). 사라지는 글자는 바닥선 아래로 가라앉는다(`data-out="under"`, 등장의 65~80%).
- **같은 것은 같은 노드로 움직인다**: FLIP `data-k`, .9~1.1s, `--ease-move`. 샘플 타이틀은 `Inbox` 가 글자 단위로 `Index` 가 된다(같은 글자는 미끄러지고, 없어지는 글자는 가라앉고, 새 글자는 떠오른다).
- **카메라**(트래킹·줌): 장면 전체를 담은 그룹의 transform 을 스텝마다 바꾼다(`--ease-move`, 1.0s 이하, 회전 금지). 샘플 흐름도는 티켓이 화면 한 자리에 머물고 세계가 흐르다가, 마지막에 전체로 물러난다.
- **펜**: 선이 그려지며 의미가 생긴다(트랙·가지·지시선). `pathLength="1"` + `data-fx="draw"`.
- **장 전환**: reveal `fade`(fast). 장 사이 연속성은 공유 요소와 카메라가 맡는다.

## 6. 기호 — 덱 전체가 같은 말을 쓴다
- AI 정거장 ○(흰 링) · 장치·관문 □(흰) · **사람 승인 ◆(주황 채움)**
- 절차 = 초록 트랙(굵기 14) · 지나온 길 = 초록 실선 · 갈 길 = `#666` 점선
- 에이전트 = 초록 원판(화면 지름 56px 이상) · 일감 = 흰 깃발 카드
- 발표마다 **시그니처 오브젝트** 하나를 정해(예: 장비를 하나씩 달며 커지는 본체) 챕터 타이틀을 그 오브젝트의 한 부분으로 줌인하며 연다.
- **동시에 나눠 맡기는 장면(팬아웃)**: 트랙에서 지선이 평행 차선처럼 갈라져 둥근 45° 꺾임으로 벌어지고, 끝마다 에이전트 원판이 달린다. 작은 흰 티켓(일감 카드의 축소판)이 지선을 따라 **같은 순간** 출발해 각 원판 앞에 선다(받은 원판 맥박 1회). 사람 ◆ 는 본선에만 둔다. (스타일 C 의 흐름 표현을 A 문법으로 옮긴 것 — 실제 발표에서 사용자가 고른 방식)

## 7-1. 실제 발표(33장)에서 검증된 장면 패턴
샘플 파일은 없지만 이 스타일로 끝까지 만들어 본 연출이다. 같은 문법으로 다시 쓰면 된다.
| 장면 | 연출 |
|---|---|
| 시그니처 시퀀스(한 섹션 12 클릭) | 흰 원판 「프로젝트」가 부품(띠·부품·팔과 창·기록선)을 하나씩 달며 커지고 → 트랙이 둘러지고 → 팬아웃 → 카메라가 물러나 같은 본체 여럿을 흰 테두리가 묶고 → 위에 지휘 자리(흰 둥근 사각)와 회색 지휘선 → 에이전트가 브라우저 창을 눌러 체크 → 초록 결과선이 지휘 자리로 돌아와 루프가 닫힘. 카메라 상태는 4개로만 묶는다 |
| 챕터 타이틀 = 시그니처로 줌인 | 앞 장이 페이드되면 시그니처 본체가 그 자리에 있고, 클릭에 그 챕터의 부품(트랙 윗변·기록선 등)으로 2.4~4.5배 줌인하며 큰 제목 |
| 이음새 | 앞 장 끝 화면의 요소(예: 기록선 다섯 줄)를 다음 장 진입 화면의 같은 자리에 둔다 — 페이드만으로도 같은 물체로 읽힌다 |
| 흐름 → 역할 레인 | 정거장 줄이 사람/AI/장치 세 레인으로 갈라져 내려앉고, 레인마다 동사 한 줄, 마지막에 일감 경로가 세 레인을 꿰며 그려짐 |
| 관문 | 한 선 위 흰 말뚝 셋. 깃발이 막히고, 조건 기호(◆○)가 채워지면 말뚝이 내려가 통과. 빨강 없음 |
| 재생 클립 | 녹화 영상 대신 장 안에서 흐르는 가상 화면(일감 카드·작업 창·자막), 승인 지점에서 멈춤 — `references/engine.md` 9절 |
| 모순 찾기 | 점검선이 두 쪽을 훑고, 어긋난 두 값에 손 동그라미 + ≠ 다리 → ○ 질문 → ◆ 답 → 틀린 쪽이 고쳐지고 ≠ 가 = 로 |
| 점검 목록 | 회색 결재선 위 꺼진 ◆ 넷 → 클릭마다 ◆ 주황 · 선이 그 자리까지 초록 · 항목이 큰 글자로(앞 항목은 회색). 체크박스 흉내 금지 |
| 마무리 | 타이틀 마지막 화면으로 돌아와 같은 자리·크기로 다시 서고, 부제 자리에 인사 |

## 8. 주의 (검증하며 나온 것)
- `vector-effect: non-scaling-stroke` + `pathLength` + `stroke-dashoffset` 을 카메라 확대·축소 월드 안에서 함께 쓰면 Chrome 에서 대시가 어긋난다. 대시를 쓰는 선은 non-scaling-stroke 를 빼고 굵기를 월드 단위로 준다.
- `data-fx` 진입 규칙은 같은 요소의 다른 `animation` 을 덮어쓴다 → fx 는 래퍼에, 맥박 같은 다른 애니메이션은 안쪽 요소에.
- 한 장 안의 긴 시퀀스(카메라가 같은 세계에서 물러나야 하는 것)는 섹션을 나누지 말고 한 섹션의 긴 스텝으로 만든다. 섹션을 나누면 사이에 페이드가 끼어 공유 요소가 끊긴다.
- 큰 그림(본체 여러 개를 한 화면에)에서는 원판이 56px 보다 작아진다 — 배율 때문이라 괜찮다. 대신 라벨 글자는 캡처 검사(실효 32px)를 통과해야 하니, 라벨은 월드 밖(화면 좌표)에 두거나 크게 쓴다.
