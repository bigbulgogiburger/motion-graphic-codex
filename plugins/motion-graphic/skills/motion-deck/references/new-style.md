# 새 스타일 만들기 — 세 스타일이 맞지 않을 때만

기본은 검증된 세 스타일(A 「무대」·B 「지면」·C 「색면과 도형」) 중 하나를 고르는 것이다. 새 스타일은 사용자가 셋 다 아니라고 하거나, 브랜드·행사 성격상 다른 시각 언어가 꼭 필요할 때만 만든다. 시간이 가장 많이 드는 단계다.

## 1. 벤치마크(레퍼런스 10건 이상)
- 출발점: Apple 키노트, Google I/O, Stripe·Linear·Vercel 런치, 토스·SLASH·당근·우아콘 같은 국내 테크 컨퍼런스, 3Blue1Brown·Kurzgesagt·Ciechanowski 같은 설명형 모션, Saul Bass 타이틀. 사용자가 든 레퍼런스가 있으면 그것부터.
- 레퍼런스마다 **무엇이 좋은지**를 수치로 적는다.
  - 타이포 스케일: 화면 높이 대비 글자 크기, 위계 비율
  - 여백, 색 절제(몇 색을 어디에)
  - 모션 언어(무엇이 어떻게 움직이고 왜), 전환 방식
  - 페이스: 장당 초, 클릭당 변화량
- 영상을 재생할 수 없으면 미리보기 프레임으로 잰다. 모션 수치는 사이트의 실제 CSS·디자인 시스템 토큰·논문에서 가져온다. 무엇을 직접 봤고 무엇이 2차 자료인지 표시한다.
- 결과는 `story/benchmark.md` 에 둔다.

## 2. 구조만 가져온다
- 가져오는 것은 **구조**다: 위계 비율, 누적 공개, 지금 것만 색, 선의 문법, 변형 전환, 도형과 의미의 대응.
- **외형은 가져오지 않는다**: 남의 그라데이션·3D·유리·글로우·파티클·고유 팔레트·캐릭터. 그것이 "AI 템플릿 느낌"과 "남의 정체성"의 원천이다.

## 3. 스타일 하나를 실제로 만든다(한 벌)
- `deck/` 안에 `theme.css`(토큰·공용 클래스)·`theme.js`(공통 연출 + `Deck.on` 등록)·`DESIGN.md`(언제 고르나 · 화면 · 색 · 조명 · 타이포 · 모션 · 기호 · 패턴)를 쓴다. 기존 스타일 폴더(`$SKILL/styles/A`)의 구성을 그대로 따른다.
- 같은 세 장으로 먼저 증명한다: **타이틀 · 큰 한 문장 · 흐름 도식**. 모션은 필름으로 확인한다.
- 사용자에게 모음 그림과 필름을 보여 주고 확인을 받은 뒤 본편으로 넘어간다. 여러 안을 만들지 않는다(사용자가 원할 때만).
- 쓸 만하면 사용자에게 묻고 `$SKILL/styles/<새 이름>/` 으로 추가해 다음 발표에서 고를 수 있게 한다(샘플 문구는 가상 예시로 바꾼다).
