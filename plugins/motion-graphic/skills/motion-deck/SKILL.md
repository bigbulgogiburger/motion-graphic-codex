# motion-deck — 말로 하는 발표를 모션그래픽 단일 HTML 로

**만드는 것**
- 발표자가 앞에서 말하고 화면이 뒤에서 돕는 발표의 슬라이드다.
- 결과물은 HTML 파일 **하나**다. CSS·JS·폰트·이미지가 다 들어 있어 인터넷 없이 Chrome 으로 열린다.
- 조작: `→`·`←` 진행, `S` 발표자 노트 창, `P` 일시정지, `F` 전체 화면.

**만들지 않는 것**
- 읽는 문서(보고서·제안서·인쇄물)는 만들지 않는다. 발표 화면은 문서 문법(챕터 라벨·푸터·범례·카드 나열)을 쓰는 순간 망가지기 때문이다.
- PDF·PPTX 도 만들지 않는다. 모션이 빠지면 이 스킬의 의미가 없다.

`$SKILL` = Codex가 읽은 이 `SKILL.md`의 실제 설치 폴더다(플러그인은 Codex 플러그인 캐시의 `skills/motion-deck/`, 폴더만 설치하면 `~/.agents/skills/motion-deck`). 명령에는 절대경로를 쓴다. 사용자와는 사용자의 언어(기본 한국어)로, 쉬운 말로 이야기한다.

## 진행 — 여섯 단계
**장 목록을 한 번 승인받은 뒤에는 납품까지 멈추지 않는다.** 단계마다 사용자를 세워 두면 발표 하나에 확인 요청이 수십 번 쌓인다. 사용자가 정해야 하는 것이 생겨도 기본값으로 진행한다. 그런 항목은 `story/status.md` 의 「사용자 확인이 필요한 것」에 모아 두고 끝에 한 번에 묻는다.

### 0. 준비
- `node --version` 이 22 이상인지 확인한다(스크립트가 내장 `WebSocket`·`fetch` 를 쓴다).
- Chrome·Edge·Chromium 이 있는지 확인한다(못 찾으면 `CHROME_PATH`).
- 프로젝트 폴더를 정한다(사용자가 준 경로, 없으면 지금 폴더 아래 새 폴더).
- 그 폴더에 이미 `deck/`·`story/status.md` 가 있으면 새로 시작하지 않는다. `status.md` 를 읽고 멈춘 단계부터 이어서 한다.
- Herdr 안인지 본다(`HERDR_ENV=1`). 4단계에서 병렬 제작을 할지 정할 때 쓴다.

### 1. 브리프 — `story/brief.md`
- 사용자가 준 자료(대본·개요·폴더·이전 발표)를 **먼저 읽고** `templates/brief.md` 를 채운다. 묻는 것은 빈칸뿐이다.
- 꼭 정할 것은 셋이다. **주제와 한 문장 메시지, 청중, 발표 시간.** 나머지는 기본값이 있다.
- 질문은 평문으로 **한 번에 하나씩** 한다.
  - 선택지는 2~4개이고, 권장안을 첫째에 두고 「(권장)」을 붙인다.
  - 이름·문구처럼 자유 서술이 필요한 것만 글로 묻는다.
- 숨겨야 할 이름(고객사·사람·내부 코드·도메인·금액)이 있는지 확인한다. 있으면 3단계 뒤 `deck/meta.json` 의 `forbidden` 에 넣는다. 빌드가 화면·노트·코드 전부를 막아 준다.
- 사용자가 대화에서 한 지시는 브리프의 「사용자가 이미 한 말」에 **원문 그대로** 옮긴다. 나중에 판단이 갈리면 그 원문을 따른다.

### 2. 스타일 — 검증된 셋 중 하나
| 스타일 | 한 줄 | 고를 때 |
|---|---|---|
| **A 「무대」** | 검정 무대에 한 번에 하나만 불을 켠다. 큰 글자가 움직이며 말하고 카메라가 따라간다 | 암전한 큰 홀, 영화적인 몰입 |
| **B 「지면」** | 흰 지면 위에 글이 조판되고 사람은 주황 펜으로 고친다 | 밝은 회의실, 결재·교정·검토 이야기 |
| **C 「색면과 도형」** | ◆ 사람 · ● AI · ■ 장치 세 도형이 배우처럼 연기하고, 글자는 자막이다 | 밝은 방, 역할·흐름 도식이 뼈대인 이야기 |

- 사용자에게 볼 곳을 알려 준다.
  - 미리보기: `$SKILL/styles/<X>/preview.html` 을 더블클릭하고 `→` 로 넘긴다.
  - 정지 화면: `shots/sheet.png`, 움직임: `shots/*-film.png`.
- 장소 조명으로 권장안을 고른다. 모르면 밝은 방(B·C)을 권한다. 근거는 `references/rules.md` 12절.
- 색은 DB Inc. 팔레트가 기본이다.
  - 사용자가 다른 브랜드 색을 주면 `deck/theme.css` 의 토큰만 바꾼다. 역할 색은 그대로 유지한다.
  - 대비는 캡처 검사가 글자 하나하나 잰다.
- 셋 다 아니라고 하면 `references/new-style.md` 로 새 스타일을 **한 벌** 만든다(가장 오래 걸린다).
- 고르면 뼈대를 만든다.
  `node $SKILL/scripts/new-deck.mjs <프로젝트> --style <X> --title "<제목>" --minutes <분>`

### 3. 장 목록 — `story/slides.md`, 한 번만 승인받는다
- `templates/slides.md` 형식으로 장마다 적는다.
  - sid, 메시지 한 문장, 화면(무엇이 어떻게 움직이나) 한 줄, 클릭 수, 예상 초, ✂(뺄 수 있음)
- **한 장에 한 생각**이다. 장당 평균 약 45초(25분 ≈ 30장 안팎)로 잡고, 합계는 발표 시간의 90% 안쪽에 맞춘다.
- **시그니처 오브젝트**를 하나 정한다. 덱 전체를 끌고 가는 그림이다(예: 장비를 하나씩 달며 커지는 본체). 챕터 타이틀을 그것으로 들어가며 열면 수십 장이 한 이야기로 읽힌다.
- 장 제목·화면 글은 이 단계부터 말투 규칙(`rules.md` 3절)을 지킨다.
- 대화에는 요약을 보여 주고 파일 경로를 알려 준다. 그다음 평문으로 한 번 승인받는다.
  - 선택지: 「승인 — 끝까지 만들기 (권장)」 / 「고칠 곳 있음」
  - 고칠 곳이 있으면 고쳐서 다시 한 번 보여 준다.

### 4. 제작 — 끝까지
1. 읽는다: `deck/DESIGN.md` → `references/rules.md` → `references/engine.md` → `references/tools.md`. 패턴은 `$SKILL/styles/<X>/samples/`(타이틀·큰 문장·흐름 도식)에서 가져온다.
2. **가장 어려운 장면부터** 만든다. 시그니처 시퀀스와 큰 그림이 먼저이고, 쉬운 장과 타이틀 다듬기는 나중이다.
3. 장 하나 = 파일 세 개다.
   - `deck/slides/<순서번호>-<이름>.html`
   - `deck/css/<sid>.css`: 선택자는 그 장 클래스로 시작한다.
   - `deck/js/<sid>.js`: 필요할 때만 `Deck.on('<sid>', …)` 로 쓴다.
   - 모든 장에 발표자 노트를 단다. 구어체 3~6문장, 클릭 자리에 `(클릭)`.
4. **끝 상태는 CSS 가 갖고, JS 는 앞으로 넘길 때 한 번 도는 연기만 얹는다.** 그래야 뒤로 가기·건너뛰기·`?static`·캡처가 늘 맞는 화면을 보여 준다.
5. 장 몇 개를 만들 때마다 검토 루프를 돈다(`tools.md`): 빌드 → 그 장만 캡처·필름 → 이슈 0 → **스크린샷을 직접 열어 본다** → 고친다.
6. 병렬 제작: Herdr 안이고 장이 12장 이상이면 챕터를 pane 에 나눈다(최대 3개, `references/parallel.md`). 아니면 혼자 순서대로 한다.
7. 사진·일러스트는 SVG/CSS 로 안 될 때만 만든다. 덱 전체에 8장 안팎이고, Codex가 직접 만든다(`references/images.md`).
8. 장 목록의 화면 제안과 다르게 만들었으면 이유를 `story/status.md` 에 한 줄 적는다.

### 5. 검사 — 다 통과해야 납품한다
- **빌드**: `node $SKILL/scripts/build.mjs <프로젝트>/deck --out <프로젝트>/dist/<이름>.html`
- **전체 캡처**: `node $SKILL/scripts/capture.mjs dist/<이름>.html out/shots --film <첫 장>@0,…`
  - 검사 이슈 0 이어야 한다. `data-audit` 예외는 정말 장식·의도된 잘림에만 쓴다.
  - 클릭이 있는 장은 필름으로 본다. 클릭당 1.2s 이하, 튕김 없음, 한 번에 한 동작.
- **눈으로 보기**
  - 모음 그림 `node $SKILL/scripts/sheet.mjs dir out/shots out/sheet.png` 으로 덱 전체 리듬을 본다.
  - 장마다 스크린샷을 열어 `rules.md` 8절 "AI 느낌" 목록과 말투 규칙으로 다시 본다.
  - 검사 통과는 최소 조건일 뿐이다.
- **내용 대조**: `story/slides.md` 의 장마다 메시지가 화면이나 발표자 노트에 빠짐없이 있는지 한 장씩 대조한다. 화면에서 뺀 풀이·사례는 노트에 있어야 한다. 사용자가 "내용 빠짐없이"를 바라는 경우가 많다.
- 여러 pane 의 장을 합쳤으면 챕터 경계의 이음새 필름(`--film <다음 장>@0`)과 합친 뒤 충돌(CSS 범위·`@keyframes` 이름)을 본다(`tools.md` 「마감 검사」).
- **단일 파일 검증**: `node $SKILL/scripts/verify.mjs dist/<이름>.html` → PASS
  - 프로젝트 밖 임시 폴더에 복사해 file:// 로 연다.
  - 외부 요청 0, 콘솔 0, 폰트, 노트, →·←·P·S, 40MB 이하를 확인한다.
  - **발표자 보기 창에서 누른 →·←·P 가 메인 화면에 닿는지**도 본다. 노트북으로 발표하면 초점은 보통 그 창에 있다.

### 6. 납품
- `dist/<이름>.html`
- `story/timing.md`: `node $SKILL/scripts/timing.mjs deck` 의 노트 기준 숫자와 제작 때 적은 장별 예상을 모아, 장별 채택 초·챕터 소계·✂ 후보와 줄이는 순서를 적는다. 사용자가 "줄이지 말라"고 하면 ✂ 는 제안으로만 남기고 장을 숨기지 않는다.
- 대화로 보고한다.
  - 파일 경로와 크기, 장 수와 예상 시간
  - 검사 결과(실제 숫자)
  - 「사용자 확인이 필요한 것」 목록
  - 한계: 못 한 것, 확인 못 한 것은 숨기지 않는다
  - 리허설 팁: `F` 전체 화면, `S` 노트(이 창에서 눌러도 →·←·P 가 메인 화면에 그대로 간다), `P` 일시정지. 발표 PC 의 "애니메이션 효과"가 꺼져 있으면 모션 줄이기 모드로 열린다. 주소 뒤 `?static` 은 모든 모션을 끈다.

## 지켜야 할 것 — 이유와 함께
- **시안은 한 벌만, 끝까지 만든다.** 사용자가 여러 안을 요청하지 않는 한 A/B 안을 만들지 않는다.
  - 고르는 일을 사용자에게 떠넘기는 것이고, 실제로 "하나만 끝까지 만들라니까"라는 지적을 받았다.
  - 지시가 애매하면 가장 단순한 하나로 읽고, 정말 갈리면 짧게 확인한다.
- **화면 글은 핵심 낱말과 평범한 말이다.** 가르치는 말투(「오늘 가져갈 것」)와 정리형 AI 말투(「맡겨 보니, 세 가지가 필요했습니다」)는 둘 다 실제로 반려됐다. 장을 이어 주는 말은 발표자가 노트를 보고 한다.
- **문서 문법을 쓰지 않는다**: 크롬(라벨·푸터·쪽번호·진행 바·범례), 카드·배지 나열, 보고서급 밀도.
- **모든 움직임에 이유가 있다**: 순서·인과·강조.
  - 장식 효과(유리·파편·글로우·파티클·필살기 전환)는 쓰지 않는다. "유리 깨지는 전환"은 실제로 반려됐다.
  - 클릭당 1.2s 이하, 튕김 없음, 자동 진행 없음(첫 장 진입 연출 3.5s 이하 하나만 예외).
- **뒷자리에서 읽혀야 한다.**
  - 읽는 문장 48px 이상, 라벨 40px 이상, 최소 32px, 대비 4.5:1 이상.
  - 한글은 `keep-all`, 서체는 Pretendard 한 벌.
- **사실은 브리프의 검증된 것만 쓴다.** 나머지는 흐리게 쓰거나 질문으로 남긴다. 숨길 이름은 빌드가 막게 `forbidden` 에 넣는다.
- **도구**
  - Playwright 는 쓰지 않는다. 무겁고 필요 없으며, 동봉한 CDP 스크립트가 같은 일을 한다.
  - 캡처는 기기 전체에서 한 번에 하나만 돈다(메모리 보호).
  - 사용자가 쓰는 Chrome 은 절대 종료하지 않는다.
- **보고는 사실대로 한다.** 돌리지 않은 검사를 통과했다고 쓰지 않는다. 실패는 출력과 함께 말한다.

## 파일 안내
| 파일 | 언제 읽나 |
|---|---|
| `references/rules.md` | 제작 전에 반드시. 말투·글자·색(DB 팔레트 대비표)·모션·도식·"AI 느낌" 목록·노트·사실·시간·밝기 |
| `references/engine.md` | 장을 만들 때. 스텝·FLIP·펜·매치컷·장별 연출 코드·발표자 보기 키·주의·재생 클립(녹화 대신 HTML 시연) |
| `references/tools.md` | 빌드·캡처·검증을 돌릴 때. 검사 이슈의 뜻과 고치는 법, 검토 루프, 마감 검사, 막힐 때 |
| `references/parallel.md` | Herdr 로 챕터를 나눌 때 |
| `references/images.md` | 사진·일러스트가 꼭 필요할 때(Codex 직접 생성) |
| `references/new-style.md` | 세 스타일이 다 맞지 않을 때 |
| `styles/<X>/DESIGN.md` · `samples/` · `preview.html` · `shots/` | 스타일을 고를 때와 그 스타일로 만들 때 |
| `templates/` | new-deck 이 `story/` 로 복사하는 브리프·장 목록·진행·타이밍 양식 |
| `scripts/` | `new-deck.mjs` · `build.mjs` · `capture.mjs` · `sheet.mjs` · `verify.mjs` · `timing.mjs` (공용 `lib.mjs`) |
| `engine/` · `vendor/reveal/` · `fonts/` | 빌드가 자동으로 넣는다. 고치지 않는다(reveal.js MIT, Pretendard OFL — 라이선스 파일 동봉) |
